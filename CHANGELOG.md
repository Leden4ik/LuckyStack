# Изменения

Номер версии вида 0.1.0: последняя цифра растёт с исправлениями, средняя с новыми
возможностями. Обновиться: `luckyctl self-update`, вернуться назад:
`luckyctl rollback luckystack`.

## 0.1.4 — 2026-11-20

- При установке PHP ставился метапакет `php`, который тянул ещё одну версию PHP
  (её потом приходилось удалять). Теперь ставится ровно выбранная версия.
- Исправлено ограничение входа в панель по имени сервера для Apache: шаблон имени
  получался пустым.
- На каждую отправку кода GitHub проверяет скрипты (ShellCheck), прогоняет тесты,
  синтаксис PHP панелей и ищет случайно попавшие пароли. Выпуск делается одним
  скриптом, который выпускает только то, что прошло проверки.

## 0.1.3 — 2026-11-15

- Кнопки «Webmail» и «phpMyAdmin» в списках ящиков и баз ISPConfig вели на порт
  8081, где ничего нет. Теперь они ведут на сайт по имени сервера
  (`/roundcube/` и `/phpmyadmin/`), а адрес `/webmail` перенаправляет на Roundcube.
  Ссылки, заданные вручную, не меняются.
- Свежий ISPConfig сам ставит панели часть заголовков безопасности, и они
  приходили дважды. Дубли убраны, у панели остаётся строгий `Referrer-Policy: same-origin`.
- Пропало предупреждение nginx «conflicting server name» на порту 80: блок
  ISPConfig для того же имени отключается, проверки Let's Encrypt для панели
  по-прежнему отдаёт наш сайт.
- При установке MariaDB больше не пишет в журнал «Upgrade failed»: пароль в
  `debian.cnf` вписывается до перезапуска.
- В отчёте о почтовых портах и на странице nginx по умолчанию теперь LuckyStack.

## 0.1.2 — 2026-11-13

- Если хостер записал в `/etc/hosts` полное имя сервера с неправильным коротким
  (например `ad-srb.example.net d-srb`), `hostname -f` не работал, и часть служб
  при установке получала короткое имя вместо полного. Теперь установщик в таком
  случае добавляет правильную строку, копия прежнего файла остаётся рядом.

## 0.1.1 — 2026-11-13

- В архиве выпуска у `server-setup.sh` и `luckyctl` не было права на запуск, и
  `./server-setup.sh` отвечал «Permission denied». Права вернул, а в инструкциях
  запуск теперь через `bash server-setup.sh`, так он не зависит от прав вообще.
- `luckyctl version` писал в источнике выпуска номер тега вместо номера коммита.

## 0.1.0 — 2026-11-13

Первый выпуск.

- Мастер установки сервера на ISPConfig: nginx из исходников с HTTP/3 и Brotli,
  несколько версий PHP, MariaDB, почта с Rspamd и Roundcube, DNS, FTP,
  сертификаты Let's Encrypt, CrowdSec и fail2ban.
- Профили установки: Минимальный, Веб + почта, Полный и Свой.
- Команда `luckyctl` для всего обслуживания: проверка здоровья, обновления,
  откат nginx, Roundcube и самого LuckyStack, бэкап и восстановление,
  версии PHP, часовой пояс, диагностика, удаление.
- Панели в ISPConfig: обслуживание сервера, уведомления, бэкапы, CrowdSec,
  fail2ban, блок-лист и доверенные IP, Node.js и Composer, заморозка vhost.
- Уведомления на почту и в Telegram, бот для разблокировки IP.
- Защита от потери доступа: после смены SSH или включения firewall нужно
  подтвердить доступ из второго окна, иначе через 5 минут всё вернётся как было.
- Проверено установкой с нуля на Debian 12 и 13, Ubuntu 22.04 и 24.04, а также
  обновлением рабочего сервера.
