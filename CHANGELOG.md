# Изменения

Номер версии вида 0.1.0: последняя цифра растёт с исправлениями, средняя с новыми
возможностями. Обновиться: `luckyctl self-update`, вернуться назад:
`luckyctl rollback luckystack`.

## Не выпущено

- Исправлена установка одной командой: `get.sh` не мог узнать последний выпуск,
  потому что обрывал чтение ответа GitHub на полуслове.

## 0.1.6 — 2026-11-20

- Панель «Обслуживание сервера»: на вкладке «Состояние» новый блок «Исправления
  безопасности и репутация почты» (то же, что `luckyctl cve` и `luckyctl blacklist`,
  с пояснениями и ссылкой на заявку в Spamhaus), новая вкладка «Изменения файлов»
  с журналом `luckyctl changes`. О находках этих проверок панель отдельно не
  оповещает, чтобы не дублировать ежедневный монитор.
- Выпуски подписываются. К релизу приложены архив, `SHA256SUMS` и подпись, а
  `luckyctl self-update` ставит новую версию, только если подпись и контрольная сумма
  сходятся. Проверка идёт через `ssh-keygen`, который есть на любом сервере.
- Установка одной командой: `curl -fsSL https://raw.githubusercontent.com/Leden4ik/LuckyStack/main/get.sh | sudo bash`.
  Скрипт скачивает последний выпуск, проверяет подпись и запускает установщик.
- В панелях бэкапов, Fail2ban, Node.js и Composer, доверенных IP, блок-листа и
  заморозки vhost стали видны заголовки разделов: тема ISPConfig прятала их класс.
  Fail2ban больше не показывает пустую плашку на каждый джейл без банов.
- Сквозные тесты: `E2E_KEEP=1` оставляет демо-клиента, `run.sh cleanup` его убирает.

## 0.1.5 — 2026-11-20

- nginx 1.30.7 и 1.31.9 с исправлениями уязвимостей (HTTP/2, HTTP/3, TLS 1.3 и
  другие, nginx.org от 18.11.2026). Сборка и так берёт последнюю версию с nginx.org,
  поднял запасные версии на случай, если сайт nginx недоступен. На уже работающем
  сервере обновить nginx: `luckyctl update nginx`.
- Новая команда `luckyctl cve`: не вышли ли исправления безопасности для того, что
  стоит на сервере. nginx сверяется со списком уязвимостей nginx.org, OpenSSL внутри
  nginx с последним выпуском своей ветки, PHP с репозиторием пакетов и php.net. Ещё
  она предупреждает о версиях PHP, которые больше не поддерживаются. То же видно в
  `luckyctl check`, а ежедневный монитор присылает уведомление, когда появляется
  что-то новое.
- Новая команда `luckyctl blacklist`: репутация почты. Проверяет обратную запись (PTR)
  внешнего IP, сам IP в чёрных списках (Spamhaus ZEN, SpamCop, PSBL, Mailspike) и
  почтовые домены в Spamhaus DBL. Spamhaus не отвечает через публичные DNS вроде
  1.1.1.1, поэтому запросы идут через локальный BIND. То же есть в `luckyctl check`,
  а монитор сообщает, если сервер или домен попал в список.
- Сквозные тесты `tests/e2e` для тестового сервера: заводят через API ISPConfig
  клиента с сайтом, базой, ящиком и DNS-зоной, проверяют сайт, почту и DNS, бэкап с
  восстановлением, уведомления и команды luckyctl, а потом убирают за собой. Запуск:
  `tools/e2e.sh root@хост порт`.
- Журнал изменений файлов: каждый шаг установки и обновления, а также add-php,
  remove-php, смена часового пояса, откат и восстановление записывают, какие файлы
  настроек они добавили, изменили или удалили. Файл, переписанный тем же содержимым,
  изменением не считается. Смотреть: `luckyctl changes` (последние шаги) или
  `luckyctl changes /etc/nginx/nginx.conf` (история одного файла).

## 0.1.4 — 2026-11-20

- При установке PHP ставился метапакет `php`, который тянул ещё одну версию PHP
  (её потом приходилось удалять). Теперь ставится ровно выбранная версия.
- Исправлено ограничение входа в панель по имени сервера для Apache: шаблон имени
  получался пустым.
- На каждую отправку кода GitHub проверяет скрипты (ShellCheck), прогоняет тесты,
  синтаксис PHP панелей и ищет случайно попавшие пароли. Выпуск делается одним
  скриптом, который выпускает только то, что прошло проверки.

## 0.1.3 — 2026-11-15

- Кнопки «Webmail» и «phpMyAdmin» в списках ящиков и баз ISPConfig вели на порт
  8081, где ничего нет. Теперь они ведут на сайт по имени сервера
  (`/roundcube/` и `/phpmyadmin/`), а адрес `/webmail` перенаправляет на Roundcube.
  Ссылки, заданные вручную, не меняются.
- Свежий ISPConfig сам ставит панели часть заголовков безопасности, и они
  приходили дважды. Дубли убраны, у панели остаётся строгий `Referrer-Policy: same-origin`.
- Пропало предупреждение nginx «conflicting server name» на порту 80: блок
  ISPConfig для того же имени отключается, проверки Let's Encrypt для панели
  по-прежнему отдаёт наш сайт.
- При установке MariaDB больше не пишет в журнал «Upgrade failed»: пароль в
  `debian.cnf` вписывается до перезапуска.
- В отчёте о почтовых портах и на странице nginx по умолчанию теперь LuckyStack.

## 0.1.2 — 2026-11-13

- Если хостер записал в `/etc/hosts` полное имя сервера с неправильным коротким
  (например `ad-srb.example.net d-srb`), `hostname -f` не работал, и часть служб
  при установке получала короткое имя вместо полного. Теперь установщик в таком
  случае добавляет правильную строку, копия прежнего файла остаётся рядом.

## 0.1.1 — 2026-11-13

- В архиве выпуска у `server-setup.sh` и `luckyctl` не было права на запуск, и
  `./server-setup.sh` отвечал «Permission denied». Права вернул, а в инструкциях
  запуск теперь через `bash server-setup.sh`, так он не зависит от прав вообще.
- `luckyctl version` писал в источнике выпуска номер тега вместо номера коммита.

## 0.1.0 — 2026-11-13

Первый выпуск.

- Мастер установки сервера на ISPConfig: nginx из исходников с HTTP/3 и Brotli,
  несколько версий PHP, MariaDB, почта с Rspamd и Roundcube, DNS, FTP,
  сертификаты Let's Encrypt, CrowdSec и fail2ban.
- Профили установки: Минимальный, Веб + почта, Полный и Свой.
- Команда `luckyctl` для всего обслуживания: проверка здоровья, обновления,
  откат nginx, Roundcube и самого LuckyStack, бэкап и восстановление,
  версии PHP, часовой пояс, диагностика, удаление.
- Панели в ISPConfig: обслуживание сервера, уведомления, бэкапы, CrowdSec,
  fail2ban, блок-лист и доверенные IP, Node.js и Composer, заморозка vhost.
- Уведомления на почту и в Telegram, бот для разблокировки IP.
- Защита от потери доступа: после смены SSH или включения firewall нужно
  подтвердить доступ из второго окна, иначе через 5 минут всё вернётся как было.
- Проверено установкой с нуля на Debian 12 и 13, Ubuntu 22.04 и 24.04, а также
  обновлением рабочего сервера.
